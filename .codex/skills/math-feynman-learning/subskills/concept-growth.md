# Concept Growth Subskill

## Role

Guide mathematical concepts to grow naturally from prior problems. Every concept should appear as a necessary response to a limitation in the previous conceptual system.

## Universal Template

For any mathematical concept, reconstruct:

```markdown
## 当前问题

...

## 旧概念的不足

...

## 新概念为什么必须出现

...

## 最小定义

...

## 最小例子

...

## 它自然引出的下一个问题

...
```

Use this diagnostic sequence:

1. What problem were we originally trying to solve?
2. What concepts did we already have?
3. Why were those concepts not enough?
4. What new object, operation, relation, or rule do we need?
5. What is the simplest version of this new concept?
6. How can we test it with a minimal example?
7. What new question does it create?

## Probability Growth Logic

- **不确定性 → 随机试验**: We need to turn uncertain phenomena into repeatable objects of discussion.
- **随机试验 → 样本空间**: We must list all possible outcomes before discussing probability.
- **样本空间 → 事件**: We often care about a class of outcomes, not one outcome.
- **事件 → 概率**: We need a number to compare how likely events are.
- **概率 → 概率公理**: Probability assignment needs rules to avoid incoherent calculations.
- **概率 → 条件概率**: New information can change probability judgments.
- **条件概率 → 独立性**: Some information changes another probability; some does not.
- **事件系统 → 随机变量**: To calculate payoff, risk, score, or average, outcomes need to become numbers.
- **随机变量 → 分布**: A random variable can take multiple values with different probabilities.
- **分布 → 期望**: Full distributions can be too detailed; we need a long-run average.
- **期望 → 方差**: Same expectation can hide different volatility.
- **方差 → 协方差 / 相关性**: With multiple variables, we need to describe co-movement.
- **多随机变量 → 大数定律**: Repeated averages stabilize toward theoretical expectation.
- **大数定律 → 中心极限定理**: Many independent random influences often produce an approximately normal sum or average.

## Expansion Rules

When asked to expand a concept into a framework:

- Give a concept chain, not a chapter outline.
- Explain why each next concept becomes necessary.
- Mark the user's current concept and the next learning question.
- Keep the chain compact unless the user asks for full notes.
